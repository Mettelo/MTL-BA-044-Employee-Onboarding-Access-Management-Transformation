# Mettelo Business Analyst Project Studio — MTL-BA-044

## Onboarding and access: technical integration analysis

**Your role:** Technical Business Analyst. This is a fictional, synthetic BA simulation in professional UK practice.

**Your commission:** How should approved employment events move between HR, service management and identity systems reliably, with accountable access decisions and recoverable failures?

**Where your work ends:** An integration analysis and assurance handover for a bounded HR-to-service-to-identity capability. No working connector, live provisioning or full organisational change programme.

Start with [the project brief](project/PROJECT_BRIEF.md), then [the exact tasks, deliverables and acceptance criteria](project/TASKS_DELIVERABLES_AND_ACCEPTANCE_CRITERIA.md). Follow [delivery and evidence releases](project/DELIVERY_GUIDE.md), [timeline](project/PROJECT_TIMELINE.md) and [assessment](project/ASSESSMENT_CRITERIA.md).

| Task | What you do | What you submit | Weight |
|---|---|---|---|
| T1 | Bound the integration | System context diagram, integration scope and ownership questions | 10% |
| T2 | Specify interface behaviour | Interface Requirements Specification | 20% |
| T3 | Define data transformation | Source-to-target mapping and technical data dictionary | 20% |
| T4 | Model event and failure paths | Sequence/event-flow diagrams and recovery specification | 20% |
| T5 | Define quality and control requirements | Non-functional and control requirements with measurable verification proposals | 15% |
| T6 | Plan integration assurance and transition | Integration test scenarios, reconciliation approach and cutover/rollback plan | 10% |
| T7 | Handover for engineering review | Technical decision record and indexed specification baseline | 5% |
